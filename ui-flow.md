# UI-Flow: Telegram-бот для голосования по групповому фото (MVP)

Этот документ описывает пользовательский поток (UI-flow) для MVP Telegram-бота, который автоматически реагирует на групповое фото в чате и запускает простое голосование **по номерам лиц**, без попытки сопоставлять людей с аккаунтами.

---

## 1. Роли и сущности

### Роли
- **Участник чата** — любой пользователь, который видит фото и сообщения бота, может голосовать.
- **Автор фото** — участник, который отправил фото (в MVP не имеет специальных прав, но может быть отмечен в сообщении бота при желании).
- **Бот** — реагирует на фото, запускает и завершает голосование.

### Сущности
- **Фото** — изображение, отправленное в чат.
- **Лицо** — найденная область лица на фото.
- **Сессия голосования** — состояние голосования для конкретного фото (список кандидатов, голоса, таймер, результаты).

---

## 2. Глобальные принципы поведения (MVP)

- Бот реагирует **только** если на фото обнаружено **≥ 2 лиц**.
- Бот не пытается определять личности пользователей (никаких @упоминаний).
- Бот не пишет в личные сообщения.
- Бот не инициирует общение без триггера-фото.
- Бот ограничивает частоту срабатываний в одном чате: **не чаще 1 раза в N минут** (например, 60 минут).
- На одно фото создаётся не более одной сессии голосования.
- Голосование длится фиксированное время (например, 20 минут).
- Один пользователь может проголосовать **один раз** (в рамках сессии).

---

## 3. Основной UI-flow (счастливый путь)

### Шаг 0 — Исходное состояние
Чат живёт своей жизнью. Бот молчит.

---

### Шаг 1 — Триггер: в чат отправляют фото
**Действие:** участник публикует фото в чат.

**Система:** бот получает событие о новом изображении.

---

### Шаг 2 — Анализ фото
**Действие (бот):** проверяет фото на наличие лиц.

**Разветвление:**
- Если найдено **0–1 лицо** → бот ничего не делает (см. раздел 4.1).
- Если найдено **≥ 2 лиц** → бот продолжает UI-flow.

---

### Шаг 3 — Сообщение бота с голосованием
**Действие (бот):** публикует сообщение-инициатор:

**Текст сообщения (пример):**
> 👀 Похоже, тут групповое фото!  
> Кто сегодня самый фотогеничный?

**Inline-кнопки (пример):**
- `👤 №1`  `👤 №2`  `👤 №3`  …  `👤 №N`

> Примечание: количество кнопок соответствует числу найденных лиц (или ограничено максимумом, например N ≤ 6).

---

### Шаг 4 — Пользователь голосует
**Действие:** участник нажимает одну из кнопок (`👤 №k`).

**Результат:**
- Telegram показывает пользователю стандартное подтверждение (например, “Вы проголосовали”).
- Бот учитывает голос и обновляет состояние сессии.

**Опционально (MVP+):** бот может отредактировать текст сообщения, добавив:
- “Голосование идёт… ⏳ (осталось 17 минут)”

Важно: не спамить чат отдельными сообщениями на каждый голос.

---

### Шаг 5 — Завершение по таймеру
**Действие (бот):** по истечении времени голосования:
- блокирует приём голосов (логически)
- публикует результаты, предпочтительно **редактированием исходного сообщения**

**Текст результатов (пример):**
> 🏆 Результаты голосования  
>  
> №2 — 5 голосов  
> №1 — 3 голоса  
> №3 — 1 голос  
>  
> Победитель: №2 🎉

**Опционально:** в конце короткий CTA:
> Хотите ещё — просто пришлите новое групповое фото.

---

## 4. Разветвления и исключения

### 4.1 На фото 0–1 лицо
**Поведение:** бот молчит (никаких сообщений).

**Причина:** чтобы не раздражать чат ложными срабатываниями и не превращаться в “спам-реактор”.

---

### 4.2 Слишком много лиц на фото
**Проблема:** на большом групповом фото может быть 10–30 лиц.

**MVP-правило (рекомендуется):**
- ограничить число кандидатов: показывать первые N лиц (например, N=6) или самые крупные N лиц.

**Сообщение (пример):**
> Нашёл много лиц — беру первые 6 для голосования 😅

---

### 4.3 Повторная обработка того же фото
**Поведение:** бот не создаёт вторую сессию.
- если возможно, сравнивает file_id / hash изображения.
- иначе — хранит “уже обработанные” сообщения в течение TTL (например, 24 часа).

---

### 4.4 Пользователь пытается проголосовать второй раз
**Поведение:** бот не меняет голос.
- опционально показывает callback-ответ: “Можно голосовать только один раз.”

---

### 4.5 Частый спам фотографиями
**MVP-защита:**
- rate-limit по чату (например, 1 сессия/60 минут).
- опционально allowlist: бот работает только в чате, где его явно включили командой админа (`/enable`).

---

## 5. Минимальные UI-элементы (Telegram)

### Сообщения
- одно сообщение для старта голосования (от бота)
- редактирование этого же сообщения для показа результатов

### Inline-кнопки
- список кнопок `👤 №1..N`
- (опционально) кнопка “Скрыть/Не показывать в этом чате” для админов — **не в MVP**, а как safety feature

---

## 6. UX-формулировки (MVP-список)

### Варианты текста вопроса (нейтральнее, меньше токсичности)
- “Кто сегодня главный герой кадра?”
- “Кому сегодня больше всего идёт камера?”
- “Выбери персонажа кадра 🙂”

### Варианты заголовка результатов
- “🏆 Итоги голосования”
- “🎉 Победитель кадра”

---

## 7. Настройки (не MVP, но зарезервировано)

Эти элементы не входят в MVP, но подразумеваются для будущих итераций:
- выбор “тона” бота (ироничный/нейтральный/деловой)
- выбор типа номинаций
- ручная разметка (“подпиши людей”)
- добровольная идентификация (“Это я”)
- аналитика по вовлечённости

---

## 8. Acceptance criteria (что считается реализованным)

1. Бот реагирует на фото только при ≥ 2 лицах.
2. Бот публикует сообщение с inline-кнопками `👤 №k`.
3. Голос каждого пользователя засчитывается не более одного раза.
4. Голосование автоматически завершается по таймеру.
5. Итоги публикуются редактированием исходного сообщения.
6. Есть rate-limit по чату (N минут между сессиями).
7. Нет попыток сопоставить лица с Telegram-аккаунтами.

---

## 9. Схема потока (кратко)

```
Фото в чат
  ↓
Бот: детект лиц
  ↓
[0–1 лицо] — молчать
  ↓
[≥2 лиц] — сообщение + кнопки 👤 №1..N
  ↓
Пользователи голосуют (1 раз)
  ↓
Таймер истёк
  ↓
Бот: редактирует сообщение → итоги + победитель
```
